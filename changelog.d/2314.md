- **Rows purged before purge markers existed now get their marker, where the purge is proven (#2314).** The companion
  cleanup removes a purged row's cursor and snapshots only for a pair with a purge marker, so rows purged before markers
  were written kept them forever. A new maintenance step writes the missing marker, naming the cursor's last event,
  when the row is missing, no work is pending, and that last event is a type whose `Apply` on the perspective can only
  purge (`PerspectiveRegistrationInfo.UnconditionalPurgeEventTypes`, from the generator's terminal-purge rule); the next
  cycle then removes the cursor and snapshots. At most 5,000 markers per cycle. A missing row can also be a row never
  created, an older eviction, or a conditional purge, and a wrong marker would make the runner skip the stream's later
  events, so **conditional purges from before markers existed are not backfilled**: those rows keep their cursor and
  snapshots, and the step logs once how many it left (counted up to 10,000). Migration 533. Nothing to change.
