- **A `Split` model's promoted fields are filled when a query returns the projected document (#2304).**
  `Query.Select(r => r.Data)`, the shape a GraphQL list field over a lens returns, came back with every promoted
  field empty, because the hydrators run only on a tracked row and a Split document does not hold those fields. The
  generator now registers each Split model's promoted columns and a copy that puts them into the document, and a query
  whose result is the projected document reads the columns beside it and applies the copy, following the hydrators'
  rules for records, `init`-only properties and nullable columns. Filtering, sorting and paging composed before the
  projection keep it hydrated, as do `Skip`, `Take` and the element operators after it; a count is unaffected. Nothing
  to configure.
