---
category: Changed
subsection: Audit
---
- **Command auditing now emits `CommandAudited` (#2470).** `EnableCommandAudit()` registered a pipeline behavior that
  nothing ran, so no command was ever audited. Command audit now runs at the gate every receptor invocation passes
  (local invoke, send, cascade, inbox delivery and every other lifecycle stage), after the receptor interceptors
  allowed it: one `CommandAudited` per receptor admitted to handle a message that implements `ICommand`, written
  before the receptor runs, so a command whose receptor fails is still recorded. A denied receptor, an event, an
  unmarked message and a type with `[AuditEvent(Exclude = true)]` are not audited. The record carries the tenant and
  user of the scope the receptor sees and the envelope's correlation and causation ids; `ResponseType` is null. A
  synchronous receptor's record is emitted fire-and-forget (a failure is logged and counted); every other receptor
  waits for its record. `AddSystemEvents(o => o.EnableCommandAudit())` is enough; a host without command audit pays
  nothing per message. **Upgrade:** `IPipelineBehavior<TRequest, TResponse>`, `PipelineBehavior<TRequest, TResponse>`
  (namespace `Whizbang.Core.Pipeline`) and `CommandAuditPipelineBehavior<TCommand, TResponse>` are removed: the
  dispatcher never ran a pipeline behavior, so an implementation never ran either. Move cross-cutting work that must
  run before a receptor to an `IReceptorInterceptor`. A command type that should be audited must implement
  `ICommand`.
