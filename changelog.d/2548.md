- **Per-message paths no longer read a message type's name unless a log or a trace needs it (#2548).** The runtime
  caches a type's name behind a weak handle, so a read with debug logging or tracing off allocated again after every
  garbage collection. The lifecycle stage skips in the receptor invoker, stream id generation and inheritance on
  dispatch and cascade, the dispatch and perspective sync activity names, and the stream id check on every event store
  append and outbox write now read the name only once the log level is enabled, a listener is attached, or the id is
  actually reported. A few startup and repair-traffic logs follow the same rule. **Upgrade:** nothing to change.
