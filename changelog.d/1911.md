---
category: Changed
subsection: Storage
---
- **A dictionary member on a perspective model stores, reads back and queries with no attribute or rewrite (#1911).**
  A `Dictionary<K,V>`, `IDictionary<K,V>` or `IReadOnlyDictionary<K,V>`, at any depth (a member, a member of a
  nested object or of a collection element, a dictionary's own value), is stored as an array of key/value objects in
  the dictionary's order, `[{"Key":"a","Value":1}]`, by both Entity Framework's mapping and the atomic upsert. Entity
  Framework no longer refuses the model. `m.Tags.ContainsKey(k)` is translated to a containment test the document's GIN
  index can answer, and `m.Tags[k]` (for a scalar value) to a lookup over the pairs; anything else on a dictionary is
  refused by Entity Framework at query time, never evaluated on the client. Reads accept the JSON object an earlier
  release wrote, counted on `whizbang.perspective.dictionary_form_fallbacks`, and the stored-form phase rewrites object
  form rows once per table (migration 544, journaled in `wh_stored_form_migrations` as `dictionary-pairs:<table>:...`).
  A key that is a date or a structure is left as an object for the reader. WHIZ810 is retired.
  **Upgrade:** a dictionary stored as one opaque document or promoted to a jsonb column with `[PhysicalField]` changes
  from a JSON object to an array of pairs; anything outside the framework that reads it with SQL (`data->'Tags'->>'x'`,
  a view, an index) must read the pairs instead (`data->'Tags' @> '[{"Key":"x"}]'`). A model rewritten by hand to a
  list of key/value objects, or split out with `[PerspectiveStorage(FieldStorageMode.Split)]` and `[PhysicalField]`, to
  satisfy WHIZ810 can go back to a plain dictionary; that is a model change of its own and needs a
  `[StoredForm]` declaration if the stored name changes. A suppression of WHIZ810 can be removed.
