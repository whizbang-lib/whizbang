---
category: Changed
subsection: Startup
---
- **The startup rollback gate judges a recorded schema change by what was applied, and makes two decisions: one for
  the W! migrations and one for the application's schema (#2553).** A change the ledger records counts as applied
  since this version only when this build does not produce the same name with the same content hash; a change this
  build defines identically is current, whatever version applied it. A database restored from another environment,
  whose ledger records a SemVer-higher application version than this build's (for example a preview build's
  `0.0.0-preview.x` against `1.63.0-rc.3`), now migrates or serves instead of standing down forever. A change this
  build does not define, and a row with no recorded hash (a stored-form or temporal-form conversion), is judged by
  who applied it, as before, and a newer version online still stands the whole instance down. The W! migrations and
  the application's schema are then judged apart, each with its own verdict and reason, logged on its own: the W!
  migrations run first; when they stand down nothing runs, and an application stand-down never blocks them, so the
  W! migrations apply and the instance then stands down, naming the application's changes. The instance serves only
  when both sides can. The incompatibility override and the lossy rollback switch can be scoped to one side with
  `Whizbang:Startup:Platform:OverrideIncompatibility`, `Whizbang:Startup:Application:OverrideIncompatibility`,
  `Whizbang:Startup:Platform:AllowLossyRollback` and `Whizbang:Startup:Application:AllowLossyRollback`; the shared
  keys keep meaning both sides. Serving the application's schema as it is no longer skips the W! migrations.
  **Upgrade:** nothing to change for a host that uses the drivers' registrations. Code that builds an
  `EFCorePostgresStartupAssessor` itself passes a `SchemaGateOverrides` (`UpgradeOrder.ReadOverrides(configuration)`)
  in place of the two booleans; code that builds a `SchemaRollbackRequest` passes the `RollbackPlan` in place of
  `AllowLossy`, and what this build defines (`IReadOnlyDictionary<string, string>` of ledger name to content hash);
  `UpgradeOrder.AppliedSince` takes that dictionary too (null judges by version alone).
