- **An integrity check that is turned off, or left on with an empty `Schedule`, no longer keeps a stored schedule
  firing (#2586).** The scheduler only ever registered schedules, so one stored while the full-history compare or
  the sealed-history re-check was on a cron kept firing afterwards: a no-op occurrence for a check that was off, and
  for a check left on with no cron a second run besides the every-Nth-audit counter. At every start the schedule
  under the check's key (`wh-integrity-sweep`, `wh-seal-recheck`) is now canceled when the check wants none, with an
  Information line when one was canceled; a key with no active schedule is a quiet no-op, a host without the
  temporal engine is unaffected, and a failed cancel is logged and does not stop the start.
  `IScheduleManager` gains `CancelByKeyAsync(key)`, which cancels a schedule by the key it was created under.
  **Upgrade:** a class that implements `IScheduleManager` itself must add `CancelByKeyAsync`.
