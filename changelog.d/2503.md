---
category: Changed
subsection: Storage
---
- **The database driver owns the archive's transaction; a storage provider only moves objects (#2503).** The archive
  coordinator moved into `Whizbang.Data.Postgres` (`PostgresObjectArchiveStore`) and writes through the new
  `IArchiveObjectStore` contract (put, get, delete, list, and the location it reaches). Its SQL, locks, manifest,
  location rows, object names and locator are unchanged, so archives written before stay readable and a rolling
  deploy beside the previous release works. A stream lifecycle policy that archives on a driver with no archive
  coordinator (SQLite), or with an object store no coordinator writes through, now fails the start naming the missing
  piece, rather than the first archive. A storage failure surfaces as `ArchiveObjectStoreException`, with the Azure
  error inside.
  **Upgrade:** `AzureBlobArchiveStore` is gone: code that resolved it (to call `RepointLocationAsync`) resolves
  `IArchiveStore` and casts it to `IArchiveObjectCoordinator` (`Whizbang.Core.Archival`).
  `ArchiveObjectCorruptedException` and `ArchiveObjectDeletionStep` moved from `Whizbang.Archive.AzureBlob` to
  `Whizbang.Core.Archival`; `ArchiveSweepMetrics` moved to `Whizbang.Data.Postgres` (its meter name is unchanged).
  Code that catches a storage failure from the archive catches `ArchiveObjectStoreException` instead of
  `Azure.RequestFailedException`.
