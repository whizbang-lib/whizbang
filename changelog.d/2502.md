- **One Azure Blob package for body offload and the event archive, active when referenced and configured (#2502).**
  `Whizbang.Storage.AzureBlob` holds both Azure Blob providers and no database code. A host that references it and
  names an account under `Whizbang:Storage:AzureBlob` (`ConnectionString`, `ServiceUri`, or `ConnectionName` naming a
  `ConnectionStrings` entry) gets each feature whose section is set (`Offloads`, `Archive`) with no registration call;
  an explicit `AddWhizbangAzureBlobStorage(...)` wins, before or after `AddWhizbang()`, and
  `WhizbangCoreOptions.AutoRegisterStorageProviders = false` keeps the package loaded but inactive. The startup log
  names the provider each feature uses and why, and warns, naming the package, when configuration names an account
  for a package that is not loaded. `Whizbang.Offloads.AzureBlob` and `Whizbang.Archive.AzureBlob` ship this release
  as shims over the new package: their registration calls are `[Obsolete]` and still work, and their keys
  (`Whizbang:Offloads:AzureBlob`, `Whizbang:Archive:AzureBlob`, and `Whizbang:BodyOffload:ProviderName` beside the new
  offload section) still bind with a startup warning naming the new key; the new key wins. Nothing stored changes.
  **Upgrade:** reference `Whizbang.Storage.AzureBlob`, move the settings to `Whizbang:Storage:AzureBlob` and remove
  the registration calls. Code that names the options or store types (`AzureBlobOffloadOptions`,
  `AzureBlobArchiveOptions`, `AzureBlobMessageBodyStore`) adds `using Whizbang.Storage.AzureBlob;`: they moved there
  from `Whizbang.Offloads.AzureBlob` and `Whizbang.Archive.AzureBlob`.
