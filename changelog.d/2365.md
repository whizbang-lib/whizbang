- **Stream integrity has its own traces, a Grafana dashboard and Prometheus alert rules (#2365).** A new activity
  source, `Whizbang.Integrity`, has spans for an audit cycle, a comparison (`integrity.audit`), an origin's answer, a
  repair request, a repair and a re-check. Manifest asks, manifests, redelivery requests and redelivery bundles carry a
  `RequestId` and a `TraceParent`, so an origin's answer and a consumer's repair join the trace that asked for them
  across services; a message from an older release carries neither and its receiver starts a new trace. Spans carry
  counts, never a stream, tenant or event id. New instruments on `Whizbang.StreamIntegrity`, none tagged per stream or
  tenant: `recheck_enabled`, `recheck_last_run_timestamp` and `recheck_coverage_ratio` (by `check`), and per lane
  `epoch_frontier` and `seal_age_seconds` (by `origin_service_id`, read by the maintainer duty's holder through
  `wh_integrity_seal_reading`, migration 490). `dashboards/grafana/whizbang-integrity.json` and
  `dashboards/prometheus/whizbang-integrity-alerts.yml` ship beside the storage dashboard, with alerts for a halted pair
  (at `PairGuard:HaltedAlertAfter`, 2 hours), a sustained deficit, re-check drift, a seal that stops advancing, a
  re-check falling behind, the retention sweep falling behind and a refused archive orphan sweep. A build test fails
  when the dashboard or a rule names a metric the library does not declare. `AddWhizbangInstrumentation()` on an
  OpenTelemetry tracer builder subscribes every Whizbang activity source (`WhizbangActivitySource.All`).
