category: Added
subsection: Context, identity & serialization

- **A strong id can accept a list of UUID versions, between UUIDv7 only and any version (#2516).**
  `[WhizbangId(Versions = UuidVersions.V7 | UuidVersions.V4)]` generates an id whose `From`, `Parse`, explicit
  cast, transport JSON reader and GraphQL scalar accept exactly the listed versions, with the RFC 9562 variant, and
  throw an `ArgumentException` naming them otherwise (`CustomerId requires UUIDv4 or UUIDv7 (RFC 9562 variant) but
  received version 5, variant 8`). It is for values the application did not make, such as ids already stored or
  issued by another system: ids it mints (`New()`) or derives through the framework (`GeneratedStreamIdentity`,
  `EmissionIdentity`, `CompositeChildIdentity`) are all UUIDv7. A value of another version is not time-ordered:
  `CompareTo` and `GetTimestamp()` do not follow creation order, and as a stream id it loses index locality.
  `Guid.Empty` is refused, `New()` still mints UUIDv7, and the constructor and `Value` initializer stay unchecked.
  `AcceptAnyVersion = true` remains the shorthand for any non-empty Guid. `Versions` defaults to `UuidVersions.V7`,
  so existing ids generate the same code. Declarations of one id (struct, property, parameter) that list different
  versions resolve to the versions they have in common, reported by the new warning WHIZ038; WHIZ029 names the
  versions an ignored `AcceptAnyVersion` opt-in resolves to, including when the lists have none in common.
  `AcceptAnyVersion = true` written with `Versions` is the new error WHIZ039, an id that accepts no version is the new
  error WHIZ043, and a `Versions` bit outside versions 1 to 8 is the new error WHIZ044.
