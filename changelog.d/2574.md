category: Fixed

- **The ephemeral pointer prune no longer fails on a pointer a cursor rests on, and the reap's scans no longer read
  every ephemeral pointer each cycle (#2574).** A perspective cursor names the last event its own perspective applied,
  which is often below the newest pointer of its stream. The opt-in pointer prune kept only the newest, so one such
  pointer in a batch failed the whole call on the cursor's foreign key, rolled back its claim, and failed again on
  every maintenance cycle without removing anything. It now leaves out any pointer a cursor or a snapshot rests on
  (migration 596). Separately, the snapshot-pairs and about-to-reap scans walked every ephemeral pointer the store had
  kept, almost all of them pointers whose bodies were already reaped, which on a long-running store cost minutes of
  database time a cycle. Both now start at a floor below which no ephemeral event has a body, advanced each cycle
  from where it last stopped (migration 597, `wh_ephemeral_reap_scan_floor`). Nothing to change; the floor's margin
  and full-rescan interval are `wh_settings` keys (`ephemeral_reap_scan_floor_margin_seconds`, default 3600, and
  `ephemeral_reap_scan_floor_rescan_seconds`, default 86400).
