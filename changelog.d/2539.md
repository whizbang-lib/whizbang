- **A `[GenerateStreamId]` command that is stored and also handled locally now has one stream (#2539).** A send that
  both writes a copy and runs the command here (a command another service owns) built several envelopes for it, and
  each generated a new stream id when `OnlyIfEmpty` was left `false`, so the stored copy and the local receptor named
  different streams for the same message. A stream generated for a message is now generated once per message instance
  and reused by every envelope built for it, outside a receptor's handling as inside one (#2537). Each new message
  still starts a fresh stream. **Upgrade:** nothing to change. Sending the same message instance again now keeps the
  stream it was given; create a new instance for a new stream.
