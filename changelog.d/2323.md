category: Changed
subsection: Storage
---
- **Stored event metadata no longer repeats the event id and the scope its row already holds (#2323).** A slim row
  leaves out its message id when it equals the row's `event_id`, and its hop scope when that scope is the row's `scope`
  column and nothing more; every read path of both stores rebuilds them from the row, so an event reads back exactly as
  before, and rows written before and after this release coexist. A message id other than the event id, a hop scope
  carrying roles, claims or principals, and full rows are kept as written. History conversion trims the slim rows
  written earlier (its walk restarts once), and the trace store's answers put both values back. No digest changes.
  `EnvelopeMetadata.MessageId` is no longer `required`, and `EnvelopeMetadata.MessageIdOf(metadata, eventId)` returns a
  stored event's message id. Migration 537. **Upgrade:** finish a rolling update of a service promptly (or update its
  instances together): once the migration runs, an instance still on an earlier release cannot read the trimmed rows,
  and rolling the library back past this release is not supported.
