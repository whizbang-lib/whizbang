---
category: Changed
subsection: Storage
---
- **A strong id inside a perspective document is stored as a UUID string, not `{"Value": ...}` (#2518).** On every
  generated perspective context, a `[WhizbangId]` is a `uuid` scalar: Entity Framework and the atomic upsert both
  write it as the UUID string, the same as a `Guid` and as the transport writes it, at any depth (nested objects,
  collection elements, nullable ids). An id predicate in a query translates to `CAST(data ->> 'OrderId' AS uuid) = @p`
  (to `data @> ...` on a model with a whole-document index), and `Contains` over ids now translates, to
  `= ANY (@ids)`, where before it threw. A read-model property can change from `Guid` to a strong id with no change to
  the stored data. The GraphQL id filters compare the id itself. A strong-id property of your own entity on a context
  with the Whizbang options extension, outside a document, now maps to a `uuid` column named after the property.
  `StoredFormFallbacks.ScalarIdentifierRead` and its `whizbang.perspective.identifier_form_fallbacks` counter are
  removed: a stored id is read only as a UUID string.
