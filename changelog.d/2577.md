category: Changed
subsection: Work coordination, perspectives & sagas

- **A caller can write streams in any order inside its own transaction and never deadlocks with a partition flip
  (#2577).** Writers now hold a partition's epoch so that only a change of the epoch waits for them: handing a
  partition over, canceling or redirecting a handover no longer waits on a write. A flip that raises the epoch (the
  old owner's acknowledgement, the deadline sweep) never waits while it holds a partition: it flips what no write
  holds and leaves the rest handing over, and the old owner asks again each second until the rest move. With
  ownership by map, a publish never raises an epoch itself: a partition leaving an owner that is no longer live
  becomes a handover with an immediate deadline, completed by the assigner's sweep on the same tick.
  **Upgrade:** nothing to change; the database functions keep their signatures. Until every instance runs this
  release, an older instance's perspective writes still block a handover while they run, so a caller writing out of
  partition order through an older instance can still meet a deadlock that PostgreSQL resolves by failing one side.
  A direct call of the acknowledgement may now return fewer partitions than it named; ask again for the rest.
