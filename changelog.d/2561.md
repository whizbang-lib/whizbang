category: Changed
subsection: Startup
---
- **The Dapper driver elects one schema migrator, through the same election as the EF Core driver (#2561).** On a
  rolling start, one Dapper instance applies the bootstrap closure, registers, wins the migrator duty and migrates;
  every other instance registers, votes, waits on the migrator's duty with its schema-ready gate shut, and then
  serves without taking the schema lock or running a pass of its own. A waiter whose migrator dies mid-migration
  votes for the duty and finishes the work. On either driver, a waiter whose migrator finished reconciles the
  perspective registry when it differs from what its own build declares (no hash covers it), and only then. The Dapper start now reports Elect (voting, then the outcome) instead of
  skipping it, and reports each committed migration file to `ISchemaInitializationObserver.OnSchemaStepCommittedAsync`.
  The election itself is shared runtime code (`MigratorElection`), which the EF Core driver's generated initializer
  now calls instead of carrying its own copy. Nothing to change.
