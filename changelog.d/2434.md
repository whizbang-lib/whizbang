category: Changed
subsection: Storage
---
- **A table larger than the online-rewrite budget is now rewritten, in a cycle of its own (#2434).**
  `Whizbang:Workers:Maintenance:OnlineRewriteMaxBytesPerCycle` used to exclude any queued table larger than the whole
  budget, so the largest tables (typically the event store and event body tables, which hold most of the index bloat)
  were never rewritten. Now the maintenance cycle that reaches such a table before any other table rewrites it and
  nothing else; one queued behind a table the cycle already took waits for a cycle of its own. A budget of `0` still
  rewrites nothing. **Upgrade:** a cycle can now copy one table larger than the budget, so the database needs free disk
  (and WAL headroom) of about that table's size while pg_squeeze or pg_repack runs. No setting restores the old
  exclusion; a budget of `0` turns online rewrites off entirely.
