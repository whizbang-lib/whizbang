---
category: Changed
subsection: Work coordination, perspectives & sagas
---
- **The Dapper driver elects its exclusive duties and runs the partition assigner, as the EF Core driver does
  (#2559).** Both Postgres drivers now register role assignment and the elected partition assigner through one shared
  registration, and a test fails if either stops doing so. On Dapper, the claim presents the published partition map
  instead of every instance ranking its peers itself, so the published assignment is the one source of stream ownership
  on both drivers. These duties now run on one elected instance instead of on every instance: the maintainer (the
  maintenance sweep and its steps such as partition maintenance, saga claim and claimed emission pruning, the
  integrity audit, checkpoint and delivery work, subscription backfill, origin reattribution, the repair drain, and
  the table rewrite at startup), the blue-green
  rebuild guard of each perspective table (a second rebuild of a table on another instance is refused as in flight), and
  the partition assigner. When the holder dies, a surviving instance takes the duty over once the holder's lease lapses.
  Schema migration on Dapper now elects one migrator too (#2561). The coordination connects with the
  driver's connection string unless `Whizbang:Database` names another, and a `roles` health component is reported.
  **Upgrade:** nothing to change in code. A Dapper service that watched the maintainer's work on every instance now
  sees it on the one instance holding the `maintainer` role (the `roles` health component names it).
- **`PartitionAssignerOptions.Enabled` is removed (#2559).** The assigner always runs, in every driver. A configured
  `Whizbang:Database:PartitionAssigner:Enabled` is reported once at startup as a removed key and changes nothing; it
  never stops the start unless unknown keys are set to throw. **Upgrade:** delete any
  `options.Enabled = ...` line from a `Configure<PartitionAssignerOptions>` call, and the
  `Whizbang:Database:PartitionAssigner:Enabled` key from configuration.
