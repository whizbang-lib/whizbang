- **RabbitMQ: a dead-lettered message lands only in its own service's dead-letter queue (#2421).** The dead-letter
  exchange was a fanout that every subscriber's dead-letter queue on an exchange was bound to, so a poison message from
  one service's queue was copied into every other service's dead-letter queue and recorded in every other service's
  dead-letter store. Each exchange now has one direct dead-letter exchange, `{exchange}.dlx.direct`; every queue sets
  `x-dead-letter-routing-key` to its own dead-letter queue name (`{queue}.dlq`), and each dead-letter queue is bound
  only on that key. **Upgrade:** RabbitMQ cannot change a queue's arguments in place, so a queue declared by an earlier
  version is deleted and declared again at startup, but only when it is empty and has no consumers. A queue that holds
  messages or still has a consumer (an instance of the earlier version) is not touched: startup fails with an error
  naming the queue. To upgrade such a queue, stop every instance still consuming from it, move or drain its messages,
  delete it, then start the new version. Plan the upgrade as a stop-then-start deploy of each service, not a rolling
  one. The earlier fanout `{exchange}.dlx` keeps working for services not yet upgraded and is deleted automatically
  once no dead-letter queue is bound to it.
