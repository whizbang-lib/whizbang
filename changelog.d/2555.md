- **Stream ownership can come from the published partition map alone, behind a per-service switch (#2555).** A
  partition ownership table (one row per partition: owner, epoch, state) is written by the partition assigner with
  every map it publishes, under its role epoch, and one predicate (`wh_i_own`) answers whether an instance may claim a
  partition. With the switch on, every claim path (outbox, inbox, perspective, multi-stream, the event fetch, outbox
  continuation and schedules) decides through that table alone: a stream's first writer is no longer pinned as its
  owner, new perspective work is leased by partition rather than to a stored owner, and a live stored owner no longer
  keeps a stream the map has moved. The switch is per service and one-way: the assigner turns it on only once every live
  instance of the service supports it, and only when `PartitionAssigner.OwnershipByMap` is set, which defaults off until
  the handover and fencing that make a moved partition safe are released. Ownership follows the incremental partition
  map (#2558): only a partition the map moves gets a new owner and epoch, and a republish of the same map writes
  nothing. Once the switch is on, an instance that does not support the mode is no assignment candidate and owns no
  partition. Off, the claims work as before. Every heartbeat now records `partition_ownership_level` in the instance's registry metadata. Migrations 565 to 567.
