subsection: Storage

- **Archiving and prefix truncation no longer wait forever on an origin whose integrity seal cannot advance (#2544).**
  With `integrity_cut_waits_for_seal` on, a cut waited while a stream held a received event at or above this service's
  verified seal for the event's origin. Two things kept such a seal at 0 for good, and every stream holding a positioned
  event from that origin was refused on every sweep:
  - **Received events stored without their origin's position.** An origin's outbox can publish an event before its
    commit-order stamper reaches it, and the receiver stores the event with no origin position. Those events sit in no
    audit window, so the windowed audit against the origin leaves its windows undecided and the seal never moves. Each
    service now asks the origin for the positions it lacks, in bounded batches per maintenance cycle, through the
    integrity request and answer exchange (`RequestOriginPositions`, `OriginPositionsAnswer`). The origin answers from
    its store or its archive table; the answer fills only missing positions, never overwrites one, refolds each sealed
    epoch the filled events fall in, records the events the origin cannot place so they are not asked again, and
    rewinds the perspectives of a stream whose order the fill changed. On by default; configure it under
    `Whizbang:StreamIntegrity:OriginPositionFill` (`Enabled`, `BatchSize` 500, `MaxBatchesPerCycle` 10, `LapPause` 30
    minutes). Watch `whizbang.stream_integrity.origin_positions_unfilled` fall and `origin_positions_filled` rise.
  - **A seal for an origin this service never audits.** The audit asks only the origins whose checkpoints reached this
    service with a request address, so a seal row for any other origin had no path to advance. The cut gate now counts a
    seal only for an origin this service audits; for any other the cut still waits for the origin lane's sealed
    frontier. Each such origin is named in a Warning every maintenance cycle and counted on
    `whizbang.stream_integrity.unaudited_seals`, so the missing checkpoint route is visible. Nothing to change.
