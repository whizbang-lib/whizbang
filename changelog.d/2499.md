---
category: Changed
subsection: Startup
---
- **An explicitly configured feature whose capability the probe cannot read now stops startup (#2499).** When the
  `Capabilities` startup step probes and a capability that an explicit setting requires still reads `Unknown` (the
  probe failed, or the server would not say, for example a role that cannot read `shared_preload_libraries`), the
  step probes again up to three times, after 1, 2 and 4 seconds, logging a warning before each. Still `Unknown`
  after the last retry, the verdict line is an error and the instance stops with exit code 4, as it already did for
  a capability known not to be usable. Before, it only warned. A requirement that is on by default still degrades
  with a warning and is never retried; with `Whizbang:Capabilities:ProbeOnStartup = false`, or for a capability no
  registered provider describes, an explicit requirement still warns. `CapabilityVerdict.Evaluate` takes a third
  argument, `probed`. **Upgrade:** give the identity the library connects as what the probe needs to read the
  capability (for Postgres, a reachable database and, for an extension that needs preloading, `pg_read_all_settings`
  so it can read `shared_preload_libraries` and `wal_level`), or remove the setting that turns the feature on. A caller of `CapabilityVerdict.Evaluate` passes `probed: true` when the
  statuses come from a probe.
