---
category: Changed
subsection: Context, identity & serialization
---
- **Event and message ids that are not UUIDv7 are refused where they enter the framework (#2528).** Version
  assignment, apply order, replay and lifecycle partitioning read the time in these ids, and the check meant to guard
  them had no caller. Every outbox and inbox write (EF Core and Dapper, each work coordinator strategy), every event
  store append (EF Core, Dapper, SQLite, in memory) and the dispatcher's caller-supplied ids (a cascade's source, a
  composite's carried child ids) now throw `GuidOrderingException` for a non-v7 id, naming the id, the message type,
  the entry point and the version, before any SQL runs, so nothing of a refused batch is written. The empty id is
  always refused. `WhizbangOptions.GuidOrderingViolationSeverity` now defaults to `Error`; at `Warning` or `Info` each
  such id is logged once and counted in `whizbang.guid_ordering.non_v7_message_ids` (meter `Whizbang.GuidOrdering`).
  **Upgrade:** mint ids with `TrackedGuid.New()` or a `[WhizbangId]` type. To find offenders without refusing them,
  set `Whizbang:GuidOrderingViolationSeverity` to `Warning` and drive the counter to zero.
- **A stream id that is not UUIDv7 is reported, not refused (#2528).** A stream id is hashed and sorted, never read for
  its time, so a non-v7 one costs only index locality: it is logged once per stream and counted in
  `whizbang.guid_ordering.non_v7_stream_ids`. `WhizbangOptions.StreamIdOrderingViolationSeverity` (default `Warning`)
  raises it to `Error` for strict stream ids. A strong id declared with `[WhizbangId(AcceptAnyVersion = true)]` is never
  reported.
- **Guid interception is on by default and replaces the call (#2528).** An intercepted `Guid.NewGuid()` or
  `Guid.CreateVersion7()` now returns `TrackedGuid.New()`, a UUIDv7 with counter precision; before, the interceptor
  wrapped the original call and its generated code did not compile. A project that does not set
  `WhizbangGuidInterceptionEnabled` gets interception; `false` turns it off, which is strongly advised against.
  `[SuppressGuidInterception]` keeps a deliberate v4. Third-party generators (Marten, UUIDNext, Medo) are no longer
  intercepted: they already return time-ordered ids. **Upgrade:** nothing for a NuGet consumer (the package allows the
  interceptors namespace); a project that references the generator as a project adds
  `<InterceptorsNamespaces>$(InterceptorsNamespaces);Whizbang.Generators.Generated</InterceptorsNamespaces>`.
- **WHIZ037 warns when a constructed or parsed Guid flows into an id (#2528).** `new Guid(bytes)`, `new Guid("...")`,
  `Guid.Parse` and `Guid.TryParse` written to a `MessageId` or `EventId` member, a `[StreamId]` member or the unchecked
  `MessageId`/`EventId` constructor (directly or through a local) carry whatever version their source had, and
  interception cannot reach them. A literal that is itself a UUIDv7 is not reported, and `From` is not either, since it
  already refuses a non-v7 Guid at run time.
