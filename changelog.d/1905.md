category: Fixed
subsection: Messaging & delivery

- **Stream-id resolution and `[GenerateStreamId]` are exact across assemblies (#1905).** Each assembly now registers
  one stream-id entry per message type it compiles, and a message resolves by its exact runtime type, falling back to
  its nearest registered base type. A derived type compiled in another assembly than its base now uses its own
  `[StreamId]` property for extraction and for setting, and its own `[GenerateStreamId]` policy, including the opt-out
  of #1893 (a type that declares its own stream id does not inherit its base's generation). Before, the base
  assembly's extractor could answer first, so the derived type's property or opt-out was ignored. WHIZ017, which
  warned about that limit, is retired. Hand-written `IStreamIdExtractor` registrations keep working: one registered
  below priority 100 is still asked first; one at or above it is asked for types no generated entry covers. Nothing to
  change; rebuild to pick up the new registrations.
