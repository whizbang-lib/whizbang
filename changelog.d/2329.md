subsection: Storage

- **The stored events of a deleted event type are retired by name (#2329).** Name the type under
  `Whizbang:EventStore:RetiredTypes:Names` and the maintenance cycle purges every stored event of it, from every stream,
  including long-lived streams it shares with types that stay, in bounded batches (`BatchStreams`, default 500;
  `MaxBatchesPerCycle`, default 10), whether or not its class still exists. The other types in those streams stay, the
  digests are recounted, a stream a destruction hold, a snapshot, the stamper or a perspective cursor holds waits whole,
  and a cursor on a retired event steps back to the event before it. A retired type is an eligibility rule: no integrity
  digest counts it on either side of a service pair, and the receive boundary turns it away (discard reason
  `RetiredType`). A name the service still declares as an event type is not retired there: its events are neither purged
  nor turned away, and every maintenance cycle logs a warning naming it. A name nothing is stored under is reported
  once. Streams a cursor or snapshot holds for good are counted in each cycle's log line and left. Rule semantics move
  to version 3 and the rules library to 3.0.0. **Upgrade:** every type's rule hash changes, so a service on this release
  and one on an earlier release halt their integrity pair until both run it, as with any rule-semantics change. Declare
  a retirement in every service that stores the type: until both sides of a pair declare it, the pair is halted for that
  type.
