---
category: Changed
subsection: Audit
---
- **An audit record the system event emitter stores locally is stored on its own id, as every other audit
  record is (#2331).** `EmitEventAuditedAsync`, `EmitCommandAuditedAsync`, and an `EventAudited` or
  `CommandAudited` given to `EmitAsync` (the path every command audit takes) appended the record to its
  tenant's audit ledger stream, so an audit perspective folded a tenant's whole trail into one row and every
  append of the tenant took one stream lock. They now append it on the record's own id, the stream a receiver
  stores a record on that the outbox path ships. The ledger stays the lane audit records travel and are
  ordered on, and `SystemEventStreams.StreamFor` now returns the record's id for an audit record. Records
  already stored stay where they are; a perspective or reader that selects audit records by type finds them
  all. **Upgrade:** code that read audit records back from `AuditLedger.StreamFor(tenant)` in the event store
  reads them by type instead (an audit perspective, or a type-filtered read).
