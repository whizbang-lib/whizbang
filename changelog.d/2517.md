subsection: Context, identity & serialization

- **A strict strong id can accept a frozen set of grandfathered values (#2517).** A generated `[WhizbangId]` type
  with the default rule or a `Versions` list declares `static partial void _isGrandfathered(Guid value, ref bool
  grandfathered)`. An id type that implements it (typically a `FrozenSet<Guid>` lookup) lets `From`, `Parse`, the
  explicit cast, the transport JSON reader and the GraphQL scalar accept the values it names even when their version
  breaks the id's rule (UUIDv7, or its `Versions` list), while every other value is still refused. Seed data with
  hand-typed ids and well-known system identities can stay as they are without opening the whole type with
  `AcceptAnyVersion = true`. Implement it without an accessibility modifier, as declared: adding `private` is CS8799.
  A grandfathered value used as a stream id is not reported as not time-ordered either. The hook is never asked about
  `Guid.Empty`, which stays refused, and `New()` still mints UUIDv7. An id that does not
  implement the hook behaves as before: the compiler removes the call. An `AcceptAnyVersion` id has no hook, since it
  refuses only the empty Guid; implementing one there is CS0759.
