category: Changed
subsection: Observability & tooling
---
- **A generated perspective runner holds only what its perspective varies; the shared runner logic is generated once
  per assembly (#2401).** Each runner repeated about 190 KB of near-constant runner logic, so a consumer's generated
  source, compile time and compiler memory grew by that much per perspective. The logic every perspective shares is now
  emitted once per assembly that has a perspective, as an internal generic base class (`PerspectiveRunnerBase.g.cs`),
  and each runner derives from it and emits only its event list, its traits, its Apply dispatch, its empty model, its
  optional overrides and its registrations: about 4 KB for a simple perspective. Runner behavior is unchanged, AOT-safe
  and reflection-free. The issue asked for the base class to live in Whizbang.Core; this ships the size win with the
  shared logic generated once per assembly instead, and moving it into Whizbang.Core, with full test coverage, is a
  follow-up. Nothing to change.
