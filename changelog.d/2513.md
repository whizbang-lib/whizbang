---
category: Changed
subsection: Rebuilds
---
- **A perspective rebuild reads its streams' events a batch at a time (#2513).** Every rebuild mode (in place,
  blue-green, named streams, and the blue-green catch-up passes) now reads the events of up to
  `Whizbang:Perspectives:Rebuild:StreamReadBatchSize` streams (default 100) with one statement, instead of one
  statement per stream, and folds each stream from that read exactly as before: the same per-stream order (stream
  version, then the origin's order for received events), checkpoints, counts and progress. A stream with archived
  data still reads its own events through the archive, and a store that cannot read a batch (for example when an
  upcaster changes an event's type) falls back to one read per stream. Set the key to 1 to read each stream on its
  own. `IPerspectiveRunner` gains `ReadRebuildEventsAsync` and `RunRebuildWithEventsAsync`, both with defaults, so a
  hand-written runner keeps working unchanged.
